# راه‌اندازی امتیازدهی عمومی REV

این سرویس جدا از Worker فعلی `rev-api` است و جایگزین آن نمی‌شود.

## ۱) ساخت جدول‌ها
در Cloudflare → Storage & databases → D1 → دیتابیس `rev-db` → Console، تمام محتوای فایل `rev-ratings-schema.sql` را اجرا کنید.

## ۲) ساخت Worker
1. در Workers & Pages یک Worker جدید با نام دقیق `rev-ratings-api` بسازید.
2. محتوای فایل `rev-ratings-worker.js` را کامل جایگزین کد Worker جدید کنید و Deploy بزنید.
3. در Settings → Bindings یک D1 database binding اضافه کنید: Variable name برابر `DB` و Database برابر `rev-db`.
4. در Variables تنظیم کنید: `ALLOWED_ORIGINS` = `https://mojtabaalimi64-cloud.github.io`
5. آدرس `/api/health` را باز کنید؛ باید `success:true` نمایش داده شود.

## ۳) بررسی
پس از انتشار سایت، از صفحه برنامه‌ریز سفر برای یک ایستگاه ۱ تا ۵ ستاره ثبت کنید. سرویس میانگین و تعداد رأی‌ها را از D1 می‌خواند و محاسبه می‌کند.

## نکات ضدتقلب و محدودیت
- هر مرورگر برای هر مورد فقط یک رأی ثبت می‌کند؛ شناسه رأی در localStorage می‌ماند و در دیتابیس فقط هش آن ذخیره می‌شود.
- محدودیت نرخ سمت سرور بر اساس IP اعمال می‌شود.
- این روش ورود/احراز هویت نیست؛ پاک‌کردن داده مرورگر یا استفاده از دستگاه/IP دیگر می‌تواند محدودیت رأی تکراری را دور بزند. برای جلوگیری قوی‌تر باید رأی‌دهنده حساب تأییدشده داشته باشد.


## ۴) مدیریت دستی میانگین رضایت از پنل ادمین
- فایل `cloudflare/rev-ratings-schema.sql` را دوباره در D1 اجرا کنید؛ دستورها `IF NOT EXISTS` هستند و جدول جدید `rev_rating_overrides` را اضافه می‌کنند.
- کد `cloudflare/rev-ratings-worker.js` را در Worker با نام `rev-ratings-api` جایگزین و Deploy کنید.
- در Settings → Variables and Secrets همان مقدار محرمانه `ADMIN_TOKEN` را که پنل ادمین REV برای Worker مدیریتی استفاده می‌کند، به‌صورت Secret در این Worker نیز تنظیم کنید. مقدار آن را داخل GitHub یا فایل HTML قرار ندهید.
- پس از Deploy، در پنل مدیریت REV زبانه «مدیریت دستی رضایت» را باز کنید؛ با شناسه، نام یا شماره تماس جست‌وجو کنید و میانگین و تعداد رأی را ذخیره کنید.
- اگر `ADMIN_TOKEN` یا جدول جدید تنظیم نشده باشد، ذخیره دستی با خطا روبه‌رو می‌شود. مسیرهای مدیریتی Worker فقط درخواست دارای `Authorization: Bearer <ADMIN_TOKEN>` را می‌پذیرند.

**شناسه اختصاصی و پیامک صاحب کسب‌وکار:** این نسخه شناسه‌های قابل‌نمایش را در پنل برای پروفایل‌های موجود تولید می‌کند، اما ارسال خودکار پیامک هنگام ثبت‌نام صاحب کسب‌وکار هنوز به جریان ثبت‌نام فروشندگان و تنظیمات API ملی پیامک متصل نشده است. برای فعال‌سازی واقعی پیامک باید آن مرحله جداگانه به Worker احراز هویت/ثبت‌نام متصل شود؛ تا آن زمان نباید پیامک ارسال‌شده را فرض کرد.


## ۵) گزارش خطای جایگاه‌ها از برنامه‌ریز سفر
- جدول `rev_station_reports` به فایل `rev-ratings-schema.sql` اضافه شده است. اجرای دوباره فایل امن است؛ جدول‌های موجود حذف نمی‌شوند.
- کد به‌روز `cloudflare/rev-ratings-worker.js` مسیر عمومی `POST /api/station-reports` و مسیرهای مدیریتی `GET /api/admin/station-reports` و `PUT /api/admin/station-reports/{id}` را اضافه می‌کند.
- در برنامه‌ریز سفر، کاربر می‌تواند نوع مشکل و توضیح اختیاری را ارسال کند. شناسه خام رأی‌دهنده ذخیره نمی‌شود؛ گزارش‌های تکراری از همان شناسه مرورگر برای یک جایگاه مسدود می‌شوند و محدودیت نرخ سمت سرور هم اعمال می‌شود.
- در پنل مدیریت REV زبانه «گزارش خطای جایگاه‌ها» اضافه می‌شود. برای مشاهده و تغییر وضعیت گزارش‌ها، Worker امتیازدهی باید به `rev-db` متصل باشد و Secret `ADMIN_TOKEN` با مقدار استفاده‌شده در پنل مدیریت تنظیم شده باشد.
- پس از اجرای SQL و Deploy کد Worker، تغییرات `trip.html` و `admin.html` با انتشار GitHub Pages در دسترس قرار می‌گیرند.
