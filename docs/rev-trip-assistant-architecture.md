# معماری دستیار سفر REV

## هدف
توسعه تدریجی برنامه‌ریز سفر خودروهای برقی به یک دستیار سفر قابل استفاده در وب و قابل انتقال به اپ اندروید؛ با حفظ صفحات فعلی و بدون افشای کلیدهای محرمانه.

## وضعیت فعلی مخزن (بررسی 2026-10-15)
- وب‌سایت روی GitHub Pages و به‌صورت فایل‌های HTML/JavaScript استاتیک منتشر می‌شود؛ بک‌اند اصلی روی Cloudflare Workers و D1 است.
- `trip.html` از Leaflet برای نقشه، سرویس مسیریابی موجود، پیش‌بینی Open-Meteo، بانک ایستگاه‌های REV/داده‌های عمومی و نمایش مسیر و شبیه‌ساز استفاده می‌کند.
- `cloudflare/rev-online-api-worker.js` سرویس آنلاین ایستگاه‌ها را با کش D1 و چند endpoint عمومی Overpass پیاده می‌کند. این داده‌ها ممکن است ناقص یا قدیمی باشند و نباید بدون منبع/زمان تأیید «زنده» یا «فعال» معرفی شوند.
- `cloudflare/rev-auth-worker.js` احراز هویت و APIهای حساب/اشتراک را ارائه می‌دهد.
- فایل `cloudflare/rev-driver-trips-schema.sql` برای تاریخچه خصوصی سفر راننده وجود دارد، اما وجود فایل SQL به معنی اجرای آن در D1 یا آماده بودن endpointهای سفر نیست. پیش از اتصال تاریخچه به حساب، باید مهاجرت و API امن آن جداگانه تأیید شوند.
- صفحه برنامه‌ریز هم‌اکنون لینک اشتراک‌گذاری تنظیمات مسیر دارد؛ این لینک مسیر و تنظیمات خودرو را در URL می‌گذارد، نه موقعیت زنده راننده.

## معماری هدف
```text
وب فعلی / PWA / اپ Android
          |
          | قرارداد JSON پایدار، نسخه‌دار
          v
REV API Gateway (Cloudflare Worker)
  |-- Navigation Adapter --> سرویس مسیریابی نشان (کلید فقط در Worker، در صورت نیاز)
  |-- Stations Adapter --> ایستگاه‌های تأییدشده REV + کش منابع عمومی
  |-- Business Adapter --> تعمیرگاه‌ها و فروشگاه‌های تأییدشده REV
  |-- Trip Service --> تاریخچه سفر، رضایت و تنظیمات خصوصی کاربر
  |-- Energy Insights --> مدل شفاف مصرف و بازه اطمینان
  |-- Share Service --> نشست اشتراک زنده با توکن تصادفی، انقضا و لغو
  |-- Media Library --> فراداده و فایل‌های موسیقی تحت مالکیت/مجوز کاربر
          |
          v
Cloudflare D1 (داده ساخت‌یافته) + Object Storage (فایل رسانه‌ای، در صورت راه‌اندازی)
```

## قابلیت‌هایی که اکنون در کد پیاده‌سازی شده‌اند
- PWA پایه: `manifest.webmanifest`، `rev-app-icon.svg` و `service-worker.js`؛ کش پوسته محدود است و query/APIها در کش قرار نمی‌گیرند.
- تاریخچه خصوصی سفر: `GET/POST /api/driver/trips`، `DELETE /api/driver/trips/:id` و `GET /api/driver/insights` در Auth Worker. هویت از نشست سرور گرفته می‌شود؛ شناسه کاربر از ورودی مرورگر پذیرفته نمی‌شود. جدول تاریخچه و index به‌صورت idempotent توسط Worker ساخته می‌شوند.
- اشتراک زنده: `POST /api/driver/shares`، `POST /api/driver/shares/:id/location`، `POST /api/driver/shares/:id/revoke` و `GET /api/driver/shares/view?token=...`. توکن خام فقط هنگام ساخت به صاحب حساب بازگردانده می‌شود؛ در D1 هش آن ذخیره می‌شود. موقعیت فقط با اجازه مرورگر ارسال می‌شود و لینک بعد از انقضا یا لغو دیگر موقعیت نمی‌دهد.
- رابط تاریخچه و اشتراک در `trip.html` و صفحه عمومی فقط‌خواندنی `share-trip.html`.

این پیاده‌سازی هنوز نیازمند آزمون عملی با حساب واقعی و مرورگر/موبایل است. تاریخچه در این مرحله با ورود دستی داده سفر پر می‌شود، نه از GPS یا خودرو به‌صورت خودکار. موسیقی و اتصال نشان به API معتبر همچنان در فازهای بعدی هستند.

## قراردادهای مهم
- رابط وب و اپ اندروید مستقیماً به دیتابیس متصل نمی‌شوند؛ فقط از API نسخه‌دار استفاده می‌کنند.
- کلید نشان، توکن امضای اشتراک، کلید پیامک/ایمیل و هر راز دیگر فقط در Secrets/Environment سمت Worker ذخیره می‌شود. هیچ راز در HTML، فایل JSON عمومی، مخزن Git یا اپ اندروید قرار نمی‌گیرد.
- هر endpoint خصوصی باید نشست کاربر را سمت سرور اعتبارسنجی کند؛ شناسه کاربر ارسالی از مرورگر به‌تنهایی قابل اعتماد نیست.
- داده GPS دقیق فقط با رضایت جداگانه و برای مدت مشخص ذخیره شود. پیش‌فرض: ذخیره‌نکردن مسیر خام GPS.
- اشتراک زنده باید opt-in باشد، توکن غیرقابل حدس داشته باشد، انقضای کوتاه، لغو فوری و صفحه عمومی فقط‌خواندنی داشته باشد. اشتراک مسیر برنامه‌ریزی‌شده از اشتراک موقعیت زنده جدا بماند.
- برآورد مصرف با برچسب «تخمینی»، فرضیات و بازه خطا نمایش داده شود؛ هیچ تضمین برد یا ایمنی ارائه نشود.
- رابط هنگام حرکت باید کم‌حواس‌پرتی باشد؛ ویرایش متن، بارگذاری موسیقی و تنظیمات در حالت توقف انجام شود.
- پخش موسیقی فقط برای فایل‌های بارگذاری‌شده/دارای مجوز مناسب باشد. مجوز پخش آنلاین یا توزیع عمومی از بارگذاری فایل به‌تنهایی نتیجه نمی‌شود.

## ماژول‌ها و ترتیب اجرا
### فاز 0 — زیرساخت وب قابل نصب (این انتشار)
- افزودن Web App Manifest، آیکون REV و Service Worker محدود به پوسته برنامه‌ریز.
- کش فقط فایل‌های پوسته مشخص؛ API، پاسخ‌های شخصی و موقعیت زنده هرگز در کش Service Worker ذخیره نمی‌شوند.
- این فاز، PWA پایه است؛ هنوز اپ Android بومی، مسیریابی نوبت‌به‌نوبت آفلاین یا نقشه آفلاین ایجاد نمی‌کند.

### فاز 1 — داده‌های مطمئن روی نقشه
- یکسان‌سازی قرارداد ایستگاه و کسب‌وکار: شناسه، مختصات، منبع، زمان آخرین به‌روزرسانی، وضعیت تأیید، توان و کانکتور.
- فیلتر عمومی فقط برای ایستگاه/کسب‌وکار تأییدشده؛ نمایش جداگانه داده‌های عمومی تأییدنشده با برچسب واضح.
- افزودن گزارش خرابی و صف بازبینی مدیر؛ ثبت تغییرات و کنترل اسپم.
- آداپتور مسیریابی نشان باید سمت سرور و پشت قرارداد REV قرار گیرد. ابتدا وضعیت قرارداد و مجوز/سهمیه API تأیید شود؛ API مسیر به‌تنهایی لزوماً راهنمای نوبت‌به‌نوبهِ صوتی/تصویری نیست.

### فاز 2 — ثبت سفر و تحلیل مصرف
- تکمیل/اعمال `rev-driver-trips-schema.sql` پس از بررسی واقعی D1، سپس endpointهای `/api/v1/trips` و `/api/v1/insights/energy`.
- ورودی‌های حداقلی: مسافت، مدت، نوع خودرو، انرژی/درصد باتری ابتدا و انتها، منبع داده و زمان. مسیر GPS خام اختیاری و خاموش به‌صورت پیش‌فرض.
- تحلیل فقط بعد از تعداد نمونه کافی؛ تفکیک برآورد دستی از OBD/API خودرو و نمایش اندازه نمونه، میانگین/میانه و پراکندگی.
- برنامه سفرهای بعدی از تاریخچه برای شخصی‌سازی استفاده می‌کند، اما هرگز جایگزین اطلاعات رسمی خودرو یا هشدار ذخیره ایمنی نمی‌شود.

### فاز 3 — موسیقی شخصی
- کتابخانه رسانه در پنل حساب با فراداده، اعتبارسنجی نوع/اندازه فایل، سهمیه و حذف/مدیریت فایل.
- فایل‌های بزرگ در Object Storage خصوصی/دارای کنترل دسترسی؛ D1 فقط فراداده. از ذخیره Base64 در D1 یا `content.json` پرهیز شود.
- پخش از طریق کنترل واضح و بدون تعامل دستی پیچیده هنگام حرکت؛ تست ادامه/توقف و محدودیت‌های پخش پس‌زمینه موبایل.

### فاز 4 — اشتراک زنده
- API آغاز/تمدید/لغو نشست، توکن تصادفی هش‌شده در D1، انقضای کوتاه، rate limit و لغو.
- دریافت موقعیت با رضایت صریح، نشانگر «اشتراک فعال»، زمان آخرین به‌روزرسانی و توقف خودکار در پایان سفر/انقضا.
- صفحه دریافت لینک فقط‌خواندنی؛ عدم نمایش نام، تلفن، شناسه حساب یا تاریخچه دیگر کاربر.

### فاز 5 — اپ اندروید
- ابتدا PWA برای نصب و آزمون رفتار روی تلفن/مانیتور؛ سپس Android shell بومی در صورت نیاز به GPS پایدار پس‌زمینه، Android Auto/Car mode یا کنترل‌های رسانه.
- اپ و وب از همان APIهای نسخه‌دار استفاده کنند. کلید API داخل APK نیز راز محسوب نمی‌شود و نباید آنجا قرار گیرد.
- Android Auto و پخش/راهنمای صوتی نیازمند رعایت محدودیت‌های پلتفرم و آزمون واقعی دستگاه است.

## معیارهای پذیرش پیش از هر انتشار
1. مسیر فعلی، محاسبه مصرف، هواشناسی، لایه ایستگاه‌ها و کسب‌وکارها و لینک اشتراک‌گذاری فعلی همچنان کار کنند.
2. خطای سرویس ثالث باعث حذف مسیر اصلی یا ادعای داده ساختگی نشود.
3. هیچ کلید محرمانه‌ای در bundle عمومی، URL اشتراکی، localStorage یا log قرار نگیرد.
4. endpoint خصوصی در نبود نشست معتبر پاسخ 401 بدهد و مجوز دسترسی به سفر فقط متعلق به همان کاربر باشد.
5. حذف حساب/درخواست حذف داده، تاریخچه و نشست‌های اشتراک مرتبط را هم پوشش دهد.
6. تست نصب PWA، حالت آفلاین محدود، موبایل، خطای API، مسیر بدون شارژر و لغو اشتراک انجام شود.

## کارهای بعدی
1. بررسی واقعی schemaها و جدول‌های موجود در D1 پیش از اجرای مهاجرت.
2. افزودن قرارداد API و endpoints امن سفر؛ تست با حساب واقعی و داده آزمایشی.
3. تکمیل آداپتور نشان و تأیید حقوقی/فنی API و سهمیه.
4. ساخت کتابخانه رسانه و نشست اشتراک زنده در Worker.
5. آزمون PWA و سپس تصمیم درباره پوسته بومی Android.
